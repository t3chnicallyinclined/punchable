# The 2026-10 UX: Tonight · Bits · Sets, and one input

The app has three tabs and one input. The input is on every screen: you say a bit or ask a question, and the app
decides which. Nothing in the data model changed: a **set list is a board** (`/api/boards`, the set builder
`/api/boards/{id}/build`), a question is an **ask conversation** (`/api/ask/chats`), a bit is an **idea**
(`POST /api/ideas`), and every write still goes through the API to the database. This page says what each screen is,
what it reads, and which old screen it replaces.

## The tabs

| Tab | Route | Reads | Replaces |
|---|---|---|---|
| **Tonight** | `/` | `GET /api/tonight/screen` (one call; changes arrive over `/api/live`) | Write (`/write`, kept), Today (`/today`, kept) |
| **Bits** | `/bits` | `GET /api/jokes?sort=performed&limit=500` (+ `q=&mode=hybrid` when searching), `GET /api/merge/candidates` | Notebook / Desk (`/notebook`, `/desk`, kept) |
| **Sets** | `/sets` | `GET /api/boards` (each board carries `names`, its jokes' short names), `GET /api/sets` under "Performed" | Boards (`/boards`, kept) |

The old tabs stay reachable as routes; nothing 404s. The sidebar on wide screens shows the same three.

## Say it or ask it: `POST /api/say`

```
POST /api/say {text, kind?: "question"|"bit"|"command", context?: {screen?, set_id?, joke_id?, board_id?}, choice?: joke id}
-> 201 {kind: "question", intent, guess, rule, overridden, text, worker, chat: <ask chat view>}
-> 200 {kind: "bit", intent, guess, rule, overridden, text, worker, idea: <POST /api/ideas result>,
        saved_to: {joke_id, title} | null, undo: {POST: "/api/undo", indexes, detach?: {POST: "/api/merge/undo", merge_id}}}
-> 200 {kind: "command", …, command: {op: "new_set", minutes, title, done: true, board: {id, title, target_s, n},
                                       undo: {PATCH: "/api/boards/<id>", body: {delete: true}}}
                        | {op: "add_to_tonight", query, words, candidates[], board,
                           done: false, ask: "which"|"none"                       (the app asks; nothing written)
                           | done: true, joke, position, created?, already?, undo: {PATCH, body: {remove: {joke_id}}}}}
```

**Commands** (2026-10-27). "new 7 for friday" / "new 5" / "make a 10 for the club" / "build me a tight 5" make a set
list (a board) of that length, named after the target ("Friday · 7"); "add <bit> to tonight" / "put the kale bit in
tonight's set" put a bit on tonight's board (the one he touched last; none yet = a new "<Weekday> · tonight" list).
The bit is matched on title and short name (word prefixes; `sure` when one hit stands clear); when it isn't sure the
response lists `candidates` and the app shows "Which bit?"; his tap sends the same text back with `choice`. A number
out of 1-240, a question mark, "what's new for friday", "the new 7 killed" are not commands (`test_say_api.COMMANDS`,
25 cases). Provenance: the parse is the classifier's `classify` event (`ai:intent`, with `command`); the board or
the add is written by him (`acted`, by him) only on his tap, or at once when the command is unambiguous and the
conversation shows Undo (the inverse board op: `PATCH {delete: true}` for a new list, `{remove}` for an add).

The classifier is deterministic and cheap: a question mark; a leading wh-word or auxiliary (what, how, do, can,
should, is, any…); a request ("build me", "give me", "new 7 for friday"); "my material / my bits / my closer".
"What if …" and "imagine …" without a question mark are premises, so bits. Everything else is a bit: a lost
punchline costs more than a misfiled question. `api-dev/tests/test_say_api.py` holds 25 examples.

**Provenance.** The text is yours; the classification is the app's. The guess is written to the `intents` store
by `ai:intent`; when the app sends `kind` (your "Not a question? Save as a bit" tap) that is an `override` event by
you; the idea or the question is then written by you through the existing flows. The classifier's guess is never
recorded as your decision. A body naming an `import:` or `ai:` actor is refused (403): this route is your own input.

`GET /api/tonight/screen` answers the whole Tonight tab in one call:
`{date, weekday, board: {id, title, target_s, runtime_s, runtime, status, status_words, weak_n, segments: [{joke_id,
short_name, duration_s, gap}], first_gap}, to_sort, latest_set, questions[3], worker, counts}`.

## Short names

Every joke has a short name: what you'd write on a paper set list. It is separate from the title.

- Stored as a joke field, `short_name` (`kb.py NODE_EDIT_FIELDS["joke"]`), written only by a decision line
  (`POST /api/decision {target: "node", action: "edit", id, after: {short_name}}`), 1 to 24 characters, `null` =
  the default. SurrealDB: `joke.short_name` (`db/schema_extra.surql`). Undo reverses it like any decision.
- Default: the title cut at its first parenthesis, then at a word break inside 18 characters
  (`creative/notebook.short_name_of`; the app's `lib/sayRules.shortNameOf` makes the same cut).
- Served on `JokeSummary.short_name`, on every `BitCard` (so the builder's steps carry it), on the boards list as
  `names`, and on the Tonight screen's segments.

## Native (iPhone) and the HIG pass (2026-10-27)

- **Recording** is one hook, `lib/recorder` (web: MediaRecorder) / `lib/recorder.native` (expo-audio
  `useAudioRecorder`, HIGH_QUALITY = AAC `.m4a`, `setAudioModeAsync({allowsRecording, allowsBackgroundRecording,
  interruptionMode: 'doNotMix'})`, the file moved to the document directory). The pipeline already takes `.m4a`
  (`api-dev/server.py AUDIO_EXT`, `engine/config.toml audio_ext`, ffmpeg in `engine/audio.py`).
- **Uploads** go through `lib/uploads` (+ `.native`): a retry queue (rules + driver in `lib/uploadsCore`, unit-tested
  with the uploader and the recorder stubbed): 5 s, 30 s, 2 min, 10 min, then every 30 min; a 4xx (except 408/429)
  is a refusal and is dropped with the server's words; the phone keeps the queue in `uploads.json` and sends with
  `expo-file-system` `uploadAsync` (background session). The record screen says how many are waiting.
- **Hold to talk** on the phone records a voice note (no on-device speech yet) and sends it as a `note`; under 0.7 s
  is a tap. The web keeps speech recognition. `● REC` shows on the button while it records.
- **Auth**: `auth/callback` is a no-op on native (the deep link must not unmount the login screen's in-flight
  request); `auth/logout` exists for the post-logout redirect; `maybeCompleteAuthSession` runs on the web only.
- **app.json**: `associatedDomains: applinks:punchable.io` (the web image serves
  `/.well-known/apple-app-site-association` as JSON with no redirect; `PK_APPLE_TEAM_ID` in infra/config.env fills
  the `TEAMID` placeholder at build), `usesNonExemptEncryption: false`, the privacy manifest reason codes
  (UserDefaults CA92.1, file timestamp C617.1, boot time 35F9.1, disk space E174.1), the microphone text.
- **Settings**: This device (Appearance System / Dark / Light, Haptics), Privacy policy and Terms, Delete my account
  and data (sends `{"confirm": "delete my material"}`; shows the API's honest answer: a request, not a deletion).
- **Appearance**: dark is the default; the app follows the system with the per-device override; the tokens are one
  mutable object (`theme.C`) swapped by `setScheme`, the tree remounts, the status bar follows. The light palette is
  `theme.LIGHT_TOKENS` (amber never carries text on light; `amber` becomes the mark colour).
- **HIG items applied everywhere touched**: 44 pt targets (to sort, +, Go, Open ›, short name, say links, search ×),
  Dynamic Type (rows scale with `PixelRatio.getFontScale`, body 17 on iOS, nothing under 11 pt), KeyboardAvoidingView
  around the input bar and every sheet, Cancel leading / Done trailing on sheets (`SheetHead`), swipe-down on the
  grabber, pull to refresh (Tonight, Bits, Sets, set list, inbox), skeletons instead of "…", one snackbar action at
  most and the snackbar above the input bar, the back button carries the previous screen's name, Reduce Motion
  (fades), haptics (selection on reorder/tabs, light on lift/hold-to-talk, success on save, warning on destructive).
- **Not done (and why)**: real expo-router Tabs with a stack per tab, native stack headers with large collapsing
  titles and `headerSearchBarOptions`, and iOS `formSheet` sheets. All three mean re-homing every screen and sheet
  under new route groups; they are the next build, not a patch (the custom bar now collapses a large title on
  scroll and labels its back button, which covers the behaviour, not the system look).

## What the owner should know

- Every set-list edit is a per-item board op. Nothing in the new screens replaces a whole list, so a phone and a
  laptop open at once don't clobber each other. Undo for those edits is the inverse op, not a decision undo.
- The Tonight screen needs one request. Polling anywhere goes through `/api/live`; the health poll runs only
  while that socket is down, and on the phone only while the app is in front.
- The AI runs on the server now (2026-10-27: the PC is retired; every model call is the Anthropic API, Opus 5.5 for
  the writing, Sonnet 5.5 for Ask and bridges, Haiku 5.5 for sorting). The conversation says "The writer is
  offline" when the server's worker hasn't checked in for 120 s, before and after a question is sent; bits save
  regardless. "AI paused for today" with the reason means the day's budget (`PK_AI_DAILY_USD`, 2.00 by default)
  is spent: the question stays queued and runs after midnight UTC. Settings > Connections shows the worker (its
  models, last check-in or the pause) instead of "your Claude, on your PC".
- Nothing on the server transcribes audio. A YouTube link or an uploaded recording is queued and honest about it:
  "Transcription happens on your phone for now; this file is waiting" (the job's `waiting_for: "transcriber"`),
  shown under the worker line and in Settings > Connections ("Transcription: on your phone (coming) · N files
  waiting"). Nothing is dropped. Transcription on the phone (iOS 26 SpeechTranscriber) is a separate build; it
  will post `POST /api/sets/transcript`, and the server then runs the text-only analysis: the bits and ideas, with
  laughs, room heat and timing marked unavailable until a recording with timing is processed.
- Settings > **Voice profile** (`/voice`, 2026-10-28): what the AI reads before it drafts in his voice, one document on
  the server (`GET/PUT /api/profile/voice`), edited in place; Save keeps the version before it and the snackbar's Undo
  restores it; court text is refused (422) and never kept. A form sheet on the phone, a page on the web. The AI never
  quotes it; it only reads it. A refusal by the model now reads "Claude declined this one: ..." instead of an error name.
- Hold-to-talk uses the browser's speech recognition (Chrome, Safari). Where there is none (Firefox) the red button
  focuses the field; on the phone it records a voice note instead. Nothing is lost.
