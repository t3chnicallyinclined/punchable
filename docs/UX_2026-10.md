# The 2026-10 UX: Tonight · Bits · Sets, and one input

The app has three tabs and one input. The input is on every screen: you say a bit or ask a question, and the app
decides which. Nothing in the data model changed: a **set list is a board** (`/api/boards`, the set builder
`/api/boards/{id}/build`), a question is an **ask conversation** (`/api/ask/chats`), a bit is an **idea**
(`POST /api/ideas`), and every write still goes through the API to the database. This page says what each screen is,
what it reads, and which old screen it replaces.

## The tabs

| Tab | Route | Reads | Replaces |
|---|---|---|---|
| **Tonight** | `/` | `GET /api/tonight/screen` (one call; changes arrive over `/api/live`) | Write (`/write`, kept), Today (`/today`, kept) |
| **Bits** | `/bits` | `GET /api/jokes?sort=performed&limit=500` (+ `q=&mode=hybrid` when searching), `GET /api/merge/candidates` | Notebook / Desk (`/notebook`, `/desk`, kept) |
| **Sets** | `/sets` | `GET /api/boards` (each board carries `names`, its jokes' short names), `GET /api/sets` under "Performed" | Boards (`/boards`, kept) |

The old tabs stay reachable as routes; nothing 404s. The sidebar on wide screens shows the same three.

## Say it or ask it: `POST /api/say`

```
POST /api/say {text, kind?: "question"|"bit", context?: {screen?, set_id?, joke_id?, board_id?}}
-> 201 {kind: "question", intent, guess, rule, overridden, text, worker, chat: <ask chat view>}
-> 200 {kind: "bit", intent, guess, rule, overridden, text, worker, idea: <POST /api/ideas result>,
        saved_to: {joke_id, title} | null, undo: {POST: "/api/undo", indexes, detach?: {POST: "/api/merge/undo", merge_id}}}
```

The classifier is deterministic and cheap: a question mark; a leading wh-word or auxiliary (what, how, do, can,
should, is, any…); a request ("build me", "give me", "new 7 for friday"); "my material / my bits / my closer".
"What if …" and "imagine …" without a question mark are premises, so bits. Everything else is a bit: a lost
punchline costs more than a misfiled question. `api-dev/tests/test_say_api.py` holds 25 examples.

**Provenance.** The text is yours; the classification is the app's. The guess is written to the `intents` store
by `ai:intent`; when the app sends `kind` (your "Not a question? Save as a bit" tap) that is an `override` event by
you; the idea or the question is then written by you through the existing flows. The classifier's guess is never
recorded as your decision. A body naming an `import:` or `ai:` actor is refused (403): this route is your own input.

`GET /api/tonight/screen` answers the whole Tonight tab in one call:
`{date, weekday, board: {id, title, target_s, runtime_s, runtime, status, status_words, weak_n, segments: [{joke_id,
short_name, duration_s, gap}], first_gap}, to_sort, latest_set, questions[3], worker, counts}`.

## Short names

Every joke has a short name: what you'd write on a paper set list. It is separate from the title.

- Stored as a joke field, `short_name` (`kb.py NODE_EDIT_FIELDS["joke"]`), written only by a decision line
  (`POST /api/decision {target: "node", action: "edit", id, after: {short_name}}`), 1 to 24 characters, `null` =
  the default. SurrealDB: `joke.short_name` (`db/schema_extra.surql`). Undo reverses it like any decision.
- Default: the title cut at its first parenthesis, then at a word break inside 18 characters
  (`creative/notebook.short_name_of`; the app's `lib/sayRules.shortNameOf` makes the same cut).
- Served on `JokeSummary.short_name`, on every `BitCard` (so the builder's steps carry it), on the boards list as
  `names`, and on the Tonight screen's segments.

## What the owner should know

- Every set-list edit is a per-item board op. Nothing in the new screens replaces a whole list, so a phone and a
  laptop open at once don't clobber each other. Undo for those edits is the inverse op, not a decision undo.
- The Tonight screen needs one request. Polling anywhere goes through `/api/live`; the health poll runs only
  while that socket is down, and on the phone only while the app is in front.
- The conversation says "Your PC is off" when the home worker hasn't claimed anything in 120 s, before and after
  a question is sent; bits save regardless.
- Hold-to-talk uses the browser's speech recognition (Chrome, Safari). Where there is none (Firefox, the phone
  build for now) the red button focuses the field; nothing is lost.
